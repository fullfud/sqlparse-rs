# Development

## Layout

| Path | What |
| --- | --- |
| `python/sqlparse_turbo/` | the package: `format`, `split`, `install`, the CLI; `django/` the Django app |
| `rust/sqlparse-front/src/` | the port: `lexer.rs`, `split.rs`, `tree.rs`, `grouping.rs`, `filters.rs`, `format.rs`, `port.rs` (about 3,800 hand-written lines). `lexer_tables.rs` and `pyunicode_tables.rs` are generated from Python by `tools/gen_lexer.py` and `tools/gen_unicode.py`; `lib.rs` and the conversions are generated by rust-anything |
| `front/` | the front door rust-anything records and replays |
| `upstream/` | sqlparse 0.6.1 (git submodule) |
| `bench/` | corpus generator (`gen_corpus.py`, same seed = same bytes), Python workload, recording inputs, `bench_package.py`, `quick_speed.py` |
| `tools/` | the checks listed in [Verification](verification.md), generators, `run_upstream_package.py`, the pictures |
| `docs/` | these pages; `docs/assets/` the pictures |

## Building and checking

```sh
git submodule update --init
python -m venv .venv && .venv/Scripts/python -m pip install -e ./upstream pytest maturin
.venv/Scripts/python -X utf8 bench/gen_corpus.py          # the corpus (not committed)
.venv/Scripts/python -X utf8 bench/make_inputs.py         # inputs for the recording

# the port, with .venv/Scripts first on PATH so rust-anything's Python sees the pinned sqlparse:
rust-anything record rust/sqlparse-front --inputs rust/sqlparse-front/inputs.jsonl
rust-anything build rust/sqlparse-front
rust-anything diff rust/sqlparse-front
rust-anything gate rust/sqlparse-front
cargo run --release --manifest-path rust/sqlparse-front/Cargo.toml --example bench_format   # Rust alone

# the package:
VIRTUAL_ENV=.venv maturin develop --release
.venv/Scripts/python -X utf8 tools/run_upstream_package.py
.venv/Scripts/python -X utf8 tools/check_package.py
.venv/Scripts/python -X utf8 tools/check_recursion.py package
.venv/Scripts/python -X utf8 bench/bench_package.py
```

`rust-anything gate` passes everything except `size`. That check compares the Rust's line count with the 59-line
front door, and most of the Rust is the generated Unicode and lexer tables.

## CI and releases

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs on every push to `main` and every pull request,
except those that change only Markdown or `docs/`:

1. the Rust: fmt, clippy, tests;
2. the wheels for each platform, and the source distribution;
3. the tests: 5 platforms x CPython 3.10-3.14, each from the built wheel. Each job runs
   [`tools/check_parallel.py`](../tools/check_parallel.py), which runs every check side by side on the
   runner's cores, the long ones cut in shares (`CHECK_SHARD=i/n`); ubuntu-latest runs the whole package check
   (`--whole --core`), the others its quick cut. The same command checks everything locally;
4. the package with other sqlparse versions (0.4.4, 0.5.3, 0.6.0).

A release is a `v*` tag. The same jobs run, then the `publish` job uploads to PyPI by trusted publishing (no token
in the repository). Bump `version` in `pyproject.toml` first.
